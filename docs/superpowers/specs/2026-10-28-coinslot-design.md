# Coin Slot 设计文档

日期：2026-10-28 · 作者：@0xasten（GitHub `beasaltfish`）· 状态：待作者审阅

## 1. 是什么，为什么做

**Coin Slot** 是一个开源的终端小游戏合集。每个游戏是一个 Claude Code mod，运行在 Claude Code 自己的面板（pane）里，不开第二个终端，也不用 tmux。使用场景是**等 Claude 跑长任务时顺手玩一局**。

**为什么做**：主要目的是给 @0xasten 的 X 账号和 GitHub 涨关注。好玩是手段，**可转发性**才是目标。因此所有取舍都偏向“截图好看、录屏好看、一眼看懂”，而不是“游戏机制做得多深”。

**卖点**（作者原话的归纳）：终端里画得像 Honu Lagoon（ASCII 格子风的潟湖动画）那样好看，而且真能玩。

## 2. 成功标准与失败标准

- **成功**：首发一周内，@0xasten 的 X 关注数增长 50%。
- **失败（反目标）**：推广效果不及预期，哪怕游戏都能跑也算失败。功能做完不等于成功。

## 3. 目标 / 非目标 / 反目标

**目标**
- 6 个原创小游戏，全部在 Claude Code 面板里可玩。
- 每个游戏都感知 Claude 的状态（见 §6）。这是相对竞品的核心差异点。
- 一行命令就能装。
- 一个街机风的展示页，可以直接截图或录屏传播。

**非目标**
- 不做桌面端和 VS Code 的适配。作者只用终端；其他界面只要给出一行“请在终端使用”的提示，不报错就行。
- 不做网页版的可玩游戏。网页只放录屏，不把游戏移植到浏览器里。
- 不做排行榜、账号、联网对战。

**反目标（出现就算做错了）**
- 复刻某个具体的现有游戏：照搬它的角色形象、美术或名字，比如 Flappy Bird 的小鸟加绿水管、Chrome 小恐龙、Tetris 的名字和方块配色。玩法类型可以保留，形象必须原创。
- 使用有版权的音乐，比如吃豆人的原曲。
- 游戏抢在 Claude 前面：Claude 需要你时，游戏还在继续跑。
- 第一屏堆满说明文字。

## 4. 约束

- **平台**：Claude Code mod API（本机 2.1.312；mod 自 v2.1.287 起可用）。只支持终端（terminal surface）。
- **默认布局是上下排列**：默认（非全屏）布局下，面板**嵌在对话下方、输入框上方**（`placement: 'inline'`）。全屏布局且终端 ≥110 列时，面板才会停靠在对话旁边（`dock`）。两种情况都要正常显示；推广素材按 inline 来做。
- **inline 面板的高度跟着内容走**：给 `Client` 写 `height="100%"`，高度会塌缩到占位那一行（reef-net 实际踩过这个坑）。必须用 `e.props.bodyColumns` 和 `e.props.scroll.bodyRows` 给出明确的宽高，并在 `$.ui.open` 时传 `rows`。
- **失焦就暂停**：面板失去键盘焦点时游戏暂停，焦点回来时继续，一局不强制做短。
- **类型检查**要用 TypeScript ≥5.9。引擎生成的 tsconfig 的 target 是 es2023，5.4 不认识。
- **品牌**：名字里不出现 “Claude”（避免商标风险），介绍里写 “for Claude Code”。
- **许可证**：MIT。

## 5. 游戏阵容（首发 6 个）

画风统一为“经典玩法 + 老派简洁像素画风”，主角和素材全部原创。下表里的游戏名是占位，最终名字由构建者提案、作者拍板。

| # | 类型 | 说明 |
| --- | --- | --- |
| 1 | 捕鱼射击 | 已完成的 `reef-net`，迁进本仓库并统一结构。数值已改成“倍率只影响花费、赔付和网的大小，捕获率只看鱼本身”，见 §9 |
| 2 | 贪吃蛇类 | 方格加一条蛇的老样子可以保留，这是通用类型 |
| 3 | 上下扑腾、穿过障碍类 | 手感和节奏照经典来；主角和障碍物原创 |
| 4 | 横向奔跑、跳跃躲障碍类 | 同上；社区里已有 claudedino，要做出区别 |
| 5 | 横版飞机射击 | 复古像素风 |
| 6 | 打砖块类 | 用鼠标拖挡板，砖块碎开时满屏粒子，录屏效果最好 |

操作上统一支持鼠标（面板里点击或移动）和键盘（方向键、空格、回车）。Esc 永远是“把焦点还给对话框”。

## 6. Claude 联动（所有游戏都有）

**第一层：Claude 叫你，游戏就让路（共享模块，6 个游戏共用）**
- 触发条件：
  - 主对话的一轮结束：`turn.complete`，过滤掉 `e.agentId !== undefined` 的子任务结束。
  - 工具判定为“问你”：`tool.check` 的判定是 `ask`。
  - Claude 向你提问：一次 `AskUserQuestion` 的 `tool.call`。
- 行为：
  - 游戏立即暂停，画面中间弹出街机式提示，比如 “CLAUDE IS DONE · ESC TO RETURN”，或者 “CLAUDE NEEDS YOU”。
  - 响一声提示音。
  - 分数和进度保留。
  - 用插件接口发一条系统通知，你切到别的窗口也能收到。

**第二层：Claude 干活，游戏里掉奖励（每个游戏各自做）**
- 每次 `tool.call`，就在游戏里生成一个**奖励物**：捕鱼冒出金鱼，贪吃蛇多一颗食物，打砖块落下道具，射击飞来补给，扑腾和跑酷多一枚金币。
- **只给奖励，不加难度。**
- 这一层的目的是让录屏里一眼看出“Claude 越忙，游戏越热闹”。

**系统通知**：用 `$.ui.notify(text, { title })`（2.1.312 类型里有）。它走用户自己配置的通知渠道（`preferredNotifChannel`），不依赖 osascript 之类的外部工具，不绑定某个操作系统；返回 `{ isSent: false, reason }` 时静默忽略。

**数据通路**：hooks 模块收到事件，更新 `$.state`，触发 Pane 重画，新的 `props` 交给正在运行的 `Client`，`Client` 的本地状态保留。上面的事件我只读了类型说明，还没实测。

**第 0 步：联动验证**（其余工作都排在它后面）。在 reef-net 上做最小验证：
1. 面板没有焦点时，`turn.complete`、`tool.check`（判定为 ask）和 `tool.call` 能否送进正在运行的 `Client`。
2. 暂停弹窗能否显示出来。
3. 系统通知能否发出。

验证失败时的退路见 §13。

## 7. 安装与分发

- 仓库：`github.com/beasaltfish/coinslot`，本身就是一个插件市场（`.claude-plugin/marketplace.json`）。
- 每个游戏是一个独立插件，另外再提供“全部安装”的方式（具体形式由构建者决定）。
- 一行安装，在插件市场还没添加时也能用。这一点已在本机 `claude plugin install --help` 里核实过：`--marketplace` 会先自动添加插件市场。
  ```
  /plugin install <game> --marketplace beasaltfish/coinslot
  ```
  在终端外面就用 `claude plugin install <game> --marketplace beasaltfish/coinslot`。
- 每个游戏一个斜杠命令打开，比如 `/reef`。
- README 第一屏：动图加这一行命令。

## 8. 展示页

已用可交互草图确认过（草图在 scratchpad 的 `page-layout-v4.html`）：

- **第一屏**只放 6 个游戏格子，铺满一屏。
  - 电脑上两行三列，手机上两列三行。
  - 除了格子上的游戏名，没有任何说明文字。
  - 底部边缘放一个很小的 “↓”，提示下面还有内容。
- 每个格子循环播放这个游戏的游戏画面，上面盖一层淡扫描线。
- **悬浮摇杆**放在底部中间：鼠标移动时朝鼠标的方向倒，按方向键时朝按键方向拨一下。
- **选择**：悬停或方向键只给一圈细边框，没选中的格子也只轻微变暗，差别很小。
- **点击或回车**：选中的格子用约 0.5 秒逐步放大铺满墙面，安装命令出现在**正中间**；按 Esc 或再点一次收回。
- **复制反馈**：点命令就复制到剪贴板。按钮变绿显示 “✓ Copied — paste into Claude Code”，同时有投币音效，飘起 “+1 CREDIT”。手机上同样能复制。
- **声音**：第一次操作后响起背景音乐（浏览器规定要先有一次交互才能出声），换格子、放大、收回、复制各有音效，右上角可以静音。
  - 首版音乐是用 WebAudio 合成的原创 8-bit 循环曲；以后再换成**原创的**经典街机风曲子。
- **第二屏**：一句话介绍、@0xasten 的 X 链接、GitHub 链接。
- **部署**：Cloudflare（作者已有账号），先用免费子域名。

**画面与性能底线**：
- 最小面板是 40 列 × 10 行，低于这个就显示“请把终端拉宽或拉高”。
- 目标帧率是 30fps。第 0 步同时在真实终端里量一次帧率。
- 如果用 `Text` 合并色块的画法撑不住，比如打砖块粒子太多，就降低渲染分辨率或减少粒子；画法本身由构建者决定。
- 各游戏的模拟和渲染分辨率跟着面板尺寸自适应。

## 9. 已有资产与教训（reef-net）

- 位置：`~/.claude/dev-mods/fcbfe306-b356-47a3-9cce-13f0dc9e3968/reef-net/`。已在作者终端里实测能玩。
- 结构：
  - `sim.ts`：纯逻辑，种子随机数，结果确定。
  - `render.ts`：纯渲染，用 `▀` 半格字符，一格显示上下两个像素。
  - `game.tsx`：`Client` 界面模块，33 ms 一帧，处理鼠标和按键。
  - `register.tsx`：注册 `/reef` 命令和面板。
- 构建者可以直接读写这个目录，把它复制进仓库后再改。
- 视觉参照：Honu Lagoon（作者给的那段 HTML，作者 @handsher_NGU，不入库）。可借鉴的是格子化的生物、潟湖渐变 `#b2f4e8 → #4ad6d6 → #1aa8ca → #0e80b6`、焦散闪光和飘过的花朵。reef-net 已经按这个调子做了，截图效果作者认可，其他游戏以 reef-net 的画面完成度为标准。
- 绘制方式：`Client` 里画不了 `Raster`（`ClientElements` 不包含它），所以用 `Text` 来画，把颜色相同的相邻格子合并成一段，以控制节点数。帧率在真实终端里没有测过。
- 捕鱼的数值：
  - 每网的捕获率是 1/hp，跟倍率无关。小鱼、海龟、蝠鲼、鲸的 hp 分别是 2、8、25、100，价值分别是 2、7、22、120。
  - 网的半径是 5 + 1.2 × 倍率。

## 10. 素材与推广

- **展示页的循环画面**用游戏自己的代码生成，不靠手工录屏：让一个自动玩家跑 `sim` 加 `render`，把格子画成视频，做到首尾无缝循环。这样画面和真实游戏完全一致，改了游戏重新生成一次就行。
- **循环画面的格式**是我的决定：页面不放视频文件，而是在 canvas 里回放录下的帧数据（每帧的字符和颜色，压缩后存成二进制）。画面更清晰，文件也更小，在手机上更轻。因此 `sim` 和 `render` 必须能脱离 Claude Code，单独在 Bun 里运行（现在已经是纯函数）。
- **推文视频**由作者真实录屏（inline 上下布局）：上面 Claude 在干活，下面在玩游戏，Claude 跑完的瞬间游戏自动暂停并弹出提示。这是全项目最重要的一幕。
- **发布节奏**：
  - 首发用合集（“6 games inside Claude Code”）。
  - 先免费发，头几个小时哪条明显比平时火，再花钱推那一条。
  - 之后按游戏逐个发深度帖。
- **发帖规矩**：第一人称，正文不放链接；正文里放安装命令，网址放在第一条回复里。

**已由作者决定**：

**我替作者做的决定**（作者可推翻）：
- Cloudflare 部署。
- 仓库结构：每个游戏一个插件，加一个共享模块。
- 循环画面用代码生成。
- 推文视频由作者真实录屏。
- 先免费发、再推火的那条。
- 名字里不放 “Claude”。

**留给构建者**：
- 共享模块的具体 API。
- 每个游戏的具体数值和关卡。
- 游戏的最终名字（提案后由作者拍板）。
- “全部安装”的形式。
- 视频编码和格式。
- 页面技术栈（只要满足 §8）。
- 测试的组织方式。
- 开发顺序。

**代码共享**是我的决定：插件的 `Client` 模块只能按路径引用本插件内部的文件，所以共享代码不能跨插件 import。做法是共享模块的源码放在仓库的 `shared/` 目录，构建时复制或打包进每个游戏插件；打包产物提交进仓库，保证从 marketplace 装上就能用。

**命名**：开发期间用工作名。**第一次公开发布之前**，作者要确认最终名字，包括插件名和斜杠命令，因为安装命令会写进推文，发出去以后就不能再改。

**开发顺序**是我的决定，时间不够时从末尾往前砍：
1. 第 0 步：联动验证
2. reef-net 迁入并接上联动
3. 打砖块（录屏效果最好）
4. 贪吃蛇
5. 横版射击
6. 扑腾类
7. 跑酷类
8. 展示页

**范围**：构建者负责游戏、展示页和 README。推广材料（推文、录屏、发布节奏执行）不在构建范围内，发布前另起一轮由作者和主 agent 一起做。关注数的基线由作者掌握。

**`claude plugin test`** 已在本机实际跑过：它运行插件目录里的 `*.test.ts`，用 `claude-code/testing` 提供的 `test`/`expect`。reef-net 的 `sim.test.ts` 和 `pane.test.tsx` 是现成的例子。

**开发流程**：Sonnet 写代码，主 agent 验证。每个游戏必须通过 `claude plugin validate`、`tsc`（≥5.9）和 `claude plugin test`，最后由作者在真实 Claude Code 里玩一遍才算完成。

## 13. 联动验证失败时的退路

作者决定：**验证失败也照样发布，不带联动**。
- 能做到的部分照做，不需要全部或全不：比如只有暂停弹窗能用，就只发暂停弹窗。
- 第二层（掉奖励）和系统通知都可以单独砍掉。
- 推广卖点随之回落到“画面好看、真能玩”。
- 失败的原因记进 README 的 roadmap，等 mod API 支持了再补上。
